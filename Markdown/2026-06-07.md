## ✅ 애플리케이션 프로토콜(CMAP) 설계 문서 작성
- 파일: [docs/02_Application_Protocol_Design.md](../docs/02_Application_Protocol_Design.md)
- 핵심: **CMAP PDU 1개 = ISO-TP 메시지 1개** 매핑
- 공통 10-byte 헤더(Magic/Version/MsgType/Flags/TransferId)
- 메시지 타입: HELLO/HELLO_ACK, META/META_ACK, DATA, ACK/NAK, FIN/FIN_ACK, ABORT/ERROR
- 청크 분할(기본 4096B) + **윈도우(블록) ACK 비트맵 재전송**
- 무결성: 전체 SHA-256 + 청크별 CRC32(옵션)
- 이어받기(Resume), 임시파일(`*.cmpart`) → 검증 후 rename
- 타임아웃/재시도 파라미터, 송/수신 상태머신 정의
- ISO-TP Open Question #2(재전송 정책) 해소: 블록 ACK 비트맵으로 누락 청크 자동 재전송

## ✅ CMAP 구현 (코덱 + 파일 송수신 서비스)
- **코덱** (`Core/Application/`)
  - `CmapProtocol`(enum/flags/codes), `Crc32`(IEEE 802.3), `CmapCodec`(전 메시지 인코딩/디코딩), `CmapMessages`
  - 공통 10-byte 헤더, Big-Endian, UTF-8 파일명
- **서비스**
  - `FileSendService` — HELLO→META→블록 DATA/ACK→FIN, 윈도우 ACK 비트맵 재전송, SHA-256, 진행률
  - `FileReceiveService` — 수락 정책 이벤트, `*.cmpart` 임시파일→검증 후 rename, 파일명 sanitize
  - `CmapInbox` — ISO-TP 메시지를 CMAP PDU로 큐잉(타입/타임아웃 수신), `CmapConfig`, `FileTransferProgress`
- **`ACK_REQUEST` 플래그 도입** — 블록 마지막 DATA에 세팅, 수신측 즉시 ACK (정적 대기 제거, 결정적). docs/02에 반영.
- **테스트 총 45개 전부 통과** (기존 24 + CMAP 21)
  - 코덱 라운드트립 11종 (CRC32 표준벡터 `0xCBF43926` 포함)
  - end-to-end 실제 파일: 빈파일/1B/4096B/4097B, 10KB 멀티블록, **1 MiB 해시 일치**, CRC off, 수신 거절

## ✅ 역할(Role) 기반 동작 추가
- `TransferRole` 도입: **송신처(Sender) / 수신처(Receiver) / 루프백 데모(LoopbackDemo)**
- `CanConnection`: 역할에 따라 서비스 선택 구성
  - 송신처 → 송신 서비스만 (수신 루프 미가동)
  - 수신처 → 수신 서비스 + 수신 루프 (로컬 채널에서 직접 수신)
  - 루프백 → 송신 + 가상 peer 수신 (Fake 전용, 검증 가드 추가)
- UI: 역할 콤보 + 역할 설명(RoleHint), 역할에 따라 **송신/수신 패널 가시성 토글**(`ShowSendPanel`/`ShowReceivePanel`)
- enum 한글 라벨 컨버터(`EnumKoreanConverter`) — 콤보에 "송신처(보내기)/수신처(받기)/루프백 데모", "Fake(가상)/Vector/PEAK" 표시
- 상태바/연결 로그에 역할 표기
- 검증: Release 전체 빌드 OK, 앱 기동(역할 UI) 정상

## ✅ 장치/채널 스캔 기능 (Vector/PEAK 시리얼·물리채널 선택)
- HAL `Discovery/`: `CanChannelInfo`, `ICanChannelEnumerator`, `CanChannelScanner`(팩토리)
  - `FakeChannelEnumerator` (가상 2채널), `PeakChannelEnumerator`(PCANBasic 실연동), `VectorChannelEnumerator`(vxlapi 실연동)
- PEAK: `PCANBasic.dll`(System32 존재) `PCAN_ATTACHED_CHANNELS`로 장치명/device_id/채널 열거
- Vector: `vxlapi64.dll` 동적 탐색(설치 폴더 자동 검색) + `xlGetDriverConfig` 파싱 → 장치명/물리채널/시리얼/채널마스크
  - ⚠ XLchannelConfig 일부 오프셋(다중채널 STRIDE, serialNumber)은 **실HW 검증 필요** (버퍼 과할당으로 안전 파싱, 예외 무발생)
- UI: 인터페이스 변경 시 자동 스캔 + [스캔] 버튼, 채널 콤보(장치명·물리채널·S/N 표시), 선택 채널이 연결에 사용
- 채널 마스크(Vector)/핸들(PEAK)을 `ConnectionSettings`에 전달 — 추후 실드라이버 open에 사용
- 테스트 `ChannelScannerTests` 3종 추가 → 전체 **51개 통과**, 앱 기동 정상
